# Literature review

Compiled from four parallel research passes (detailed notes with per-claim access labels in
`research/agent_notes/A–D`) plus the main session's own reading. Access level is stated per source:
**full** = full text read, **partial** = parts/abstract read or text extraction partly garbled,
**code** = author source code read, **secondary** = only via other papers, slides or summaries.
Statements of the form "we infer" are our hypotheses, not findings of the cited work.

## 3. What the review implies for this project

1. **Interface gap.** The predictor sees only `ip` and the outcome of every branch (all types). Published IMLI, backward-path and loop-exit techniques assume the target is known. No source found infers branch direction from the address of the next *predicted branch*; the closest is a ChampSim pull request that uses the next *instruction* address, which a predictor callback does not receive. **Our N1 claim is limited to this inference and its use for IMLI in a PC-only interface.**
2. **Where MPKI is.** mcf and xz dominate mean MPKI and are H2P-dominated (Lin & Tarsa; confirmed on our traces by agent C's measurement). Large-footprint effects are small in these particular trace regions (agent C counted only 44 distinct branches in the gcc window).
3. **Allocation management.** Global throttling exists (Seznec 2014/2024/2025, BATAGE CAT); per-branch filtering exists only as "hand the branch to another predictor" (Bullseye) or as type/bias filters. A per-branch, payoff-gated allocation throttle is not found in the literature searched; agent C's prototype measured a small effect (−0.2% to −0.6% mean MPKI, deepsjeng sometimes worse) — to be verified in our implementation.
4. **Expected size of gains.** The literature puts SC at ~8%, loop ~0.3%, IMLI 0.2–7% depending on traces. Realistic targets: beat the 64 KB hashed perceptron clearly (via TAGE-SC-L), then show incremental, ablation-verified gains from N1/N2.
